# Solvent-induced frontier orbital shifts in chalcogen-containing D–A–D oligomers

Data and analysis code for the article
*"Solvent-induced frontier orbital shifts in chalcogen-containing donor–acceptor–donor oligomers and their prediction from gas-phase calculations"*
by Özge Özkılınç, Emire Şen Uyanık, Esra Nur Doğan and Hakan Kayi (Ankara University).

The repository contains the B3LYP/LANL2DZ isolated and acetonitrile PCM frontier orbital energies of 48 chalcogen-containing
donor–acceptor–donor systems (monomer to hexamer; 575 entries, 287 isolated/PCM pairs), the TD-B3LYP/LANL2DZ band data,
and the Python code that reproduces all tables and figures of the article (data audit, correction models M0–M4, grouped
cross-validation, learning curves, transfer and calibration tests).

* `data/` – transcribed source tables (CSV) with table and page locators
* `supplementary/Supplementary_Data_S1.xlsx` – the same data with audit flags and cross-validated predictions (Supplementary Data S1 of the article)
* `src/`, `run_all.py`, `run_extension.py` – analysis code
* `results/`, `figures/` – outputs regenerated by the code (TIFF files are written when the scripts are run)

**Source data.** All values were transcribed from two MSc theses (Ankara University, 2021): Ö. Özkılınç (A and B systems,
Tables 4.2–4.4) and E. Uyanık (C systems, Tables 4.2, 4.5 and 4.6). Values are kept as reported (see `data/source_corrections.csv` for the one documented sign correction); entries flagged by
the audit are not corrected. No new electronic-structure calculations were performed.

All values are kept as reported in the source theses; entries flagged by the audit are not corrected. The only change is a
sign typo in the source table (PCM LUMO of the A-SSS hexamer, listed as +3.63 eV), corrected to −3.63 eV after confirmation by
the authors of the calculations; it is documented in `data/source_corrections.csv` and applied in `src/audit.py`.
LC-BLYP results, B3LYP/6-31G(d) values and extrapolated polymer gaps are not used in the models.

## Usage

```
pip install -r requirements.txt
python run_all.py
python run_extension.py
python make_supplementary.py
```

`run_all.py` takes a few minutes (mostly the learning curve). Results are written to `results/`
(A/B analysis) and `results/extension/` (three-framework analysis); figures to `figures/`.

Random seeds: grouped bootstrap 42 (5000 resamples), learning curve 1, C calibration draws 17.
Tested with Python 3.12, NumPy 2.3, pandas 2.2, scikit-learn 1.8 and Matplotlib 3.10
(exact versions in requirements-lock.txt).

## Data settings and tests

* **S1** – all pairs, Huber loss (ε = 1.35); no manual exclusion
* **S2** – A/B pairs passing rules R1–R3, ordinary least squares
* **S3** – S2 without mixed-provenance series (161 A/B pairs; 257 pairs including C), ordinary least squares
* **Leave-one-combination-out CV** – all chain lengths of one XYX combination withheld (in A and B, or in A, B and C)
* **Learning curve** – k random training combinations; a draw is accepted only for a full-column-rank design
  (M3: every chalcogen indicator must vary). Accepted counts in `learning_curve_summary.csv`, full record in
  `learning_curve_rank_diagnostics.csv`
* **Direct transfer** – M2/M3 fitted to A/B only and applied to C (no C term)
* **Pooled CV** – C indicator added; the same XYX withheld in A, B and C
* **C calibration** – screened A/B data plus k C reference combinations (100 draws per k); the A/B pairs of the
  predicted XYX combinations stay in training, so these errors are not equivalent to pooled CV
* **M4** – sensitivity model with C-specific slopes

Learning-curve and calibration errors are retrospective estimates on screened records. Optical screens are
heuristic and do not assign excited states; `optical_screen_sensitivity.csv` and
`results/extension/optical_sensitivity.csv` report alternative thresholds.
